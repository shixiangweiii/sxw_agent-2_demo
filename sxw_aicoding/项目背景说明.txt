## 简介说明（更新于 2026/8/10 20:00）

这是一个基于公司生产项目简化后的用于我个人学习和准备面试的项目源码，不承担真实线上流量；

这个项目相关的改动不要受既有技术债和历史兼容包袱约束，新代码不得主动制造缺乏明确收益的技术债；

保持简洁，不需要兼容旧 API、旧行为和旧业务数据，也不要保留 schema migration 机制，也不要为了旧数据保留兼容层；

只管大胆使用最先进、最优秀、生产级的技术方案思路即可，但是需要具备生产级的思考和设计并工程素养在线，如生产级考虑的边界case处理、状态机设计严谨性；
    “生产级”：除边界 case 和状态机外，至少还应包含：并发竞争、幂等、超时与重试、部分失败、资源上限、背压、安全、可观测性和故障恢复；
    技术方案要先进，但必须成熟可验证、与问题匹配，并且新增复杂度有明确收益；

具体代码层面保持简洁直白、变量、代码、注释、文档等语义明确、不要故意秀语法炫技重点在于设计方案上的先进性不在于语法糖；
    “直白优于模式堆砌”但不是允许失控的长函数、重复逻辑和复杂分支；
    宁可选择容易理解的线性流程，也不要为了套用设计模式制造无价值的间接层；但仍需控制函数复杂度、封装稳定职责并消除实质性重复；

不要滥用设计模式优先选择可直接阅读的线性流程，不为了套用设计模式制造无价值的间接层、做好封装、做好合适层次的抽象、组合优于继承（慎用继承，继承控制在2级之内即 Base -> Sub，不允许 Base -> Middle -> Sub）；

思考设计要“生产级”，生产目标方案必须支持多实例和跨节点协作，比如一开始就要考虑实际集群化分布式，如果缺少相关中间件依赖可以提出来一起讨论，比如“回复停止”的功能停止流式生成不要用单机内存来记录状态，而是引入必要的中间件如 Redis 作为中心化协调器；
    本地开发和测试允许使用单机适配器，但不得把只能在单进程或单节点上保证正确性的实现定义为生产目标方案；
    涉及共享状态、任务调度、会话、取消、租约、幂等、副作用或进度管理的生产目标方案，必须考虑多实例和跨节点协作；
    目前使用 SQLite 的现状处理：暂时先维持现状，目前本地开发可以使用单机实现，但不能让进程内存成为跨进程状态的唯一权威；

对于现有历史代码暂时不做一次大改动后续慢慢小步重构即可；

对于新生成的代码要遵守以上最新的要求；
    未触及的历史代码暂不强制改造；
    新增代码和本次修改所触及的代码遵守新规则，不为了顺手清理而扩大改动范围；
    每次小步重构都必须独立正确、可测试；
    不能长期（临时双写或过渡适配必须有明确用途、删除条件和验证方式，不得成为最终状态）保留双写或两套语义；

最后：具体开发过程中，遇到输入的要求和此项目背景约束有冲突之处，主动提出来一起讨论；
