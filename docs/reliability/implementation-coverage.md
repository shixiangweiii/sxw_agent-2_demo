# REL/FI 实现覆盖追踪

快照日期：2026-08-09  
范围：当前共享源码树的 `tests/reliability/`  
性质：实现覆盖清单；不修改 [可靠性测试目录](reliability-test-catalog.md) 中冻结的目标断言。

覆盖标记：

- **DIRECT**：测试显式建立目标边界并断言主要结果；允许用可重复的异常/重建模拟进程 kill。
- **PARTIAL**：已有测试覆盖核心不变量或相邻边界，但表中列出的目标断言仍缺少直接自动化证明。
- **GAP**：没有可归因的自动化测试。仅有源码实现、人工 smoke 或文档不算覆盖。

节点采用 `pytest` 的 `文件::函数` 形式；参数化函数表示其全部参数实例。`scripts/check.sh` 校验 30 个 REL、12 个 FI 均有且只有一行，并校验所列测试文件与函数真实存在。**整个 pytest suite 通过不等于 PARTIAL/GAP 已满足冻结退出条件。**

## 3. 使用规则

1. 新测试若关闭某个 PARTIAL/GAP，更新本表的节点、覆盖标记和剩余缺口；不得只改标记。
2. 删除或重命名测试时同步更新节点；`scripts/check.sh` 会对悬空节点 fail-fast。
3. R3 的冻结退出条件仍是 30 个 REL 与 12 个 FI 全部 DIRECT；当前 `pytest` 全绿只能证明表内现有测试全绿。
4. 真实 LLM smoke、四服务五进程启动和行为评分不替代本表中的确定性可靠性测试。
